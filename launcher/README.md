# Ball Territory War · CLI 启动器

终端界面（TUI）启动器：查看环境状态、实时订阅战况、启动/构建游戏、图形化编辑全部 56 个
平衡参数。录制视频 / 背景音乐 / 限制 60fps / 武器升力**恒定开启**，不提供开关。
纯 C++17 + POSIX，无第三方依赖，与游戏同一个 CMake 构建。

- 产物：`build/btw-launcher`
- 构建：`cmake --build build --target btw-launcher`（或项目根 `scripts/run_launcher.sh`）
- 与游戏的关系：启动器**不修改也不链接游戏代码**，只通过
  `~/.ball/config.yaml`、`~/.ball/launcher.conf` 与游戏遥测 socket 交互。

## 目录结构

```
launcher/
├── README.md
└── src/
    ├── main.cpp        # 入口：子命令解析 + 配色探测 + TUI 启动
    ├── term.{h,cpp}    # 终端层：raw 模式、按键解码（含 UTF-8）、单元格屏幕缓冲、ANSI
    ├── json.{h,cpp}    # 极简 JSON 解析（解析遥测帧）
    ├── config.{h,cpp}  # 56 键 schema、YAML 行级读写、启动选项持久化
    ├── telemetry.{h,cpp}  # 遥测 socket 客户端 + SETCONFIG 下发
    ├── project.{h,cpp}    # 项目根定位、环境探测、cmake 构建、fork/exec 启动游戏
    └── tui.{h,cpp}        # 真彩主题、主面板与配置面板的绘制与交互
```

### 配色与外观

- **真彩（24bit）自动探测**：`COLORTERM` 含 `truecolor`/`24bit` 时启用 24bit 主题
  （深色面板底色、按游戏显示层配色的队伍色、进度条、状态徽标）；否则自动退回基本 16 色。
- 命令行可强制：`--truecolor` / `--16color` / `--no-color`（也支持标准的 `NO_COLOR` 环境变量）。
- 队伍配色与游戏 `NEW_FRAME_PALETTE` 一致（红 #ff9696 / 绿 #64ff64 / 蓝 #b4d2ff / 黄 #fff08c）。
- 队伍状态徽标：存活显示领土百分比，**基地失守但有物理球正在复活飞行 → 「复活中」**（队伍名
  保持队伍色），彻底出局才是「已灭」（暗色 + 红色）。依据遥测 `alive` / `reviving` 两个数组。
- 内容区最宽 120 列并居中，超宽终端下不会被拉散；窗口尺寸变化会自动重排。
- `--ascii`：用 ASCII 边框（`+`/`-`/`|`）替代圆角制表符。

### 主面板按键

| 按键 | 作用 |
|---|---|
| `Enter` / `o` | 编辑录像输出文件名（支持中文等 UTF-8 字符） |
| `l` | 启动游戏（会二次确认，需再按 `y`） |
| `b` | 构建：在 `build/` 执行 `cmake .. && make` |
| `r` | 刷新环境状态 |
| `c` | 打开配置面板 |
| `q` | 退出 |

### 配置面板

| 按键 | 作用 |
|---|---|
| `↑` `↓` `PgUp` `PgDn` `Home` `End` | 浏览 11 组 56 键 |
| `Enter` | 编辑当前项（数字，越界自动夹取到 schema 范围） |
| `w` | 保存到 `~/.ball/config.yaml` **并**通过 socket 实时应用 |
| `a` | 仅实时应用（不写文件） |
| `d` | 全部恢复默认值（需确认；再按 `w` 才会写入） |
| `r` | 从磁盘重新读取 |
| `Esc` | 返回主面板（`q` 在面板内也可退出，有未保存改动时先确认） |

改动过的项显示 `●`；标 `重启` 的项只在下次启动游戏时生效；面板底部会显示当前选中项的
完整键名与说明。

## 非交互子命令

终端不可用时（脚本、CI）可直接用子命令，行为与界面一致：

```bash
btw-launcher status                      # 环境状态
btw-launcher build                       # cmake + make
btw-launcher args                        # 打印将传给游戏的命令行（不启动）
btw-launcher launch --dry-run            # 同上；去掉 --dry-run 才真的启动
btw-launcher config list                 # 列出 56 键与当前值
btw-launcher config get paintBalls.speed # 查询单键（文件缺失时回退默认值）
btw-launcher config set paintBalls.speed 150
btw-launcher config set lift.weaponInitial 60000 90000 120000
btw-launcher config apply combat.absorbRatio 25   # 只实时应用，不写文件
btw-launcher config reset                # 全部恢复默认并写入
btw-launcher telemetry -s 3              # 打印 3 秒遥测帧（--raw 输出机器可读格式）

# 输出文件名可与任意子命令组合（并会被记住）
btw-launcher --output run1.mp4 args
```

## 配置文件

| 文件 | 说明 |
|---|---|
| `~/.ball/launcher.conf` | 只保存录像输出文件名（`output=...`），编辑后即时写入；旧文件里的 record/music/limit_fps/weapon_lift 会被忽略 |
| `~/.ball/config.yaml` | 游戏配置。启动器采用**行级替换**写入，保留缩进、顺序与 `#` 注释；文件不存在时按 schema 生成带注释的默认文件 |

- 文件中缺失的键（例如游戏版本更新后新增的配置项）**会自动补写**到所属分组的末尾
  （分组不存在则在文件末尾新建，并标注"启动器补充"），补写的键会在界面消息里提示，
  因此旧配置文件也能继续用界面编辑新参数。
- 数值按 schema 的 min/max 夹取；非法数字直接拒绝（子命令退出码 2）。
- 启动器 schema 与游戏 `src/core/config.cpp` 的键一一对应；改游戏配置键时需同步
  `launcher/src/config.cpp` 的表。

## 与游戏进程的交互

- **遥测**：连接 `/tmp/btw_telemetry.sock`，读取每行一个 JSON 的战况帧（游戏侧 0.5s 采样
  一次、50ms 重复推送）；游戏未运行时每 0.8s 退避重连，界面显示 OFFLINE。
- **热更新**：`SETCONFIG <点分键> <值...>` → `OK` / `ERR <原因>`，用独立短连接逐条下发。
- **启动游戏**：`fork + execv` 启动 `build/main`，工作目录为项目根，
  `stdout/stderr` 重定向到 `build/game.log`（界面底部实时显示末尾几行），
  这样游戏日志不会糊掉 TUI。
- **退出检测**：`waitpid(WNOHANG)` 回收子进程并在状态栏显示退出码。

## 自动化测试提示

界面用 pty 驱动即可脚本化验证：分配伪终端 → 写入按键字节（方向键为 `\x1b[A/B`）→
读取输出并用一个小型终端模拟器还原屏幕。开发时用这种方式覆盖了主面板渲染、开关切换、
启动二次确认（只确认提示、不真的启动）、配置编辑与越界夹取、中文输入与退格、
真彩/16 色/无色三种模式、窗口过小提示等场景。
